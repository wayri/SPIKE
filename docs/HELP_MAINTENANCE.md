# Integrated help maintenance and coverage

The desktop Help browser loads lazily and bundles its text and evidence images offline. It includes authored introductory and analysis workflow topics, the workbench handbook, FAQ, top-level engineering documentation, a compiler-derived JSX control inventory, command help generated by the SPIKE CLI parser, and the immutable error registry. Raw Markdown HTML is rendered as text, never executed.

## Regeneration and verification

From app/ run:

```text
npm run help:generate
npm run test:help
npm exec tsc -- --noEmit
npm run build
```

Regenerate after changing CLI flags, error metadata or UI controls. The help test rejects stale generated catalogs and checks search ranking, complete catalog keys, internal links, unsafe Markdown handling, all reference-document rendering and packaged PNG availability. No solver runs during generation. The frontend control scan uses the installed TypeScript compiler, not a JSX regex.

## Control coverage boundary

The control inventory records every matched JSX button/input/select/textarea and shared Tool/MenuItem/Numeric/NumberField/TextField location in top-level app/src TSX files, excluding the help implementation. A mapped component is recorded once at its source location. Context-dependent labels are explicitly marked. Source locations and availability expressions are expandable technical references, not substitute user instructions. The handbook explains the workflows, prerequisite sequence and interpretation of results.

Dynamic options, controls generated outside these JSX primitives, and every runtime state are not claimed as exhaustively exercised. Add authored explanations and representative runtime captures as these controls evolve. Do not call a static inventory complete interaction verification.

## Authored interface and analysis coverage

Keep the **Clean and Classic workspace** article synchronized with `appSettings.ts`, `WorkspaceHeader.tsx`, `FocusCommandPanel.tsx`, `WorkspaceEditorTabs.tsx`, `HiddenToolsMenu.tsx` and the viewport tool components. Clean is the default; the ribbon and optional quick-tools bar start hidden. Record exact visible labels for Menu and global command search, document tabs, hidden-tool recovery, selection filters and the independent workspace/viewport appearance settings. Classic remains a supported alternate layout.

The authored analysis index covers PI, SI, EM, Thermal, hybrid/multi-solve, CHT, CFD and multi-board workflows. Each topic must state prerequisites, inputs, outputs, diagnostics, conservation or convergence evidence and actual capability limits from `docs/SOLVER_STATUS.md`. Keep reduced models, external adapters and experimental native routes distinct. A prepared case, UI availability or imported field does not promote model status.

The authored topics link to `doc:docs/ANALYSIS_GALLERY.md` and `doc:docs/UI_QUICKSTART.md`. The gallery must label workflow diagrams, browser screenshots and plots from executed results separately. Do not describe an unobserved native screen as captured or use a diagram as solver evidence.

## Navigation and local state

Help links use help:ARTICLE_ID#SECTION and can be pasted into help search. They are internal documentation addresses, not operating-system protocol registrations. Diagnostic opens select the exact registered code; unknown codes remain unknown. Bookmarks and checklist progress are local preferences and never edit a project. Help traps focus and prevents project keyboard shortcuts while open. Ctrl+F focuses help search; Escape closes an enlarged image before closing help. Print styles isolate the current article.
