# ADR 0142: Exact capability destinations without promotion of qualification

- Status: Accepted for development integration
- Date: 2026-10-24

## Context

The solver presentation catalog and dependency snapshot lagged implemented specialized worker services and panels. Generic Python links opened unrelated/default scripts, and a requested absent extension could visually fall back to another tool. Integration must not promote source-only numerical experiments into production board dispatch.

## Decision

The frontend capability index carries optional exact `templateId` and explicit `sourceOnly` metadata. A capability opens its existing typed panel, stages its exact guarded request runner, opens the requested external adapter, or presents evidence without a runnable action. Missing templates, changed project generation and source-only requests fail closed. Templates are dynamically loaded and never run merely by navigation.

Python remains authoritative for the preview-only block dependency graph; the bundled JSON snapshot must equal that graph and map each presentation capability exactly once. A generated human-readable destination guide is checked against the same catalog. Catalog references are bundled into offline Help.

Existing specialized services retain numerical/runtime admission and result contracts. Ten new runners use reviewed `{request: ...}` inputs, bounded input files, no implicit launch, exclusive result export and the existing provenance guard for publishing generic results. Multiport fixture removal joins common guided Run/Tutor using the live request and dedicated panel. Heavy-method classification is explicit in frontend and thin native host.

## Consequences and evidence

No numerical kernel, production registry solver identity, material assumption, tolerance, physical-validation state or release gate is changed. Source-only board-volume RT0 and development-native references remain outside general production dispatch. Installed-worker availability and physical qualification remain distinct.

Tests cover every indexed destination, staged source identity, missing-template/source-only/project-switch refusal, actual service dispatch with numerical owners mocked, dependency snapshot parity, fixture lifecycle, and native heavy admission. See [integration map](../SOLVER_INTEGRATION.md).
