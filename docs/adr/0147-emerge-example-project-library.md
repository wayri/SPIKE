# ADR 0147: EMerge example projects and exact probe recipes

- Status: accepted for development, 25 October 2026
- Owners: example packaging, TypeScript presentation, existing project lifecycle

## Decision

Package existing admitted EMerge results and source/config evidence as native
v3 projects and lazy inline desktop snapshots. Catalog, build manifest, example
metadata and probe recipes have explicit `spike/emerge-gallery*` v1 identities.
The builder invokes the existing project writer/reader and result admission;
it never dispatches EMerge or manufactures missing result bindings.

Four projects retain solver samples. The multilayer/two-port example is setup
only because the retained raw result lacks a complete authoritative source
binding. Historical results are unchanged, with current-import differences
recorded explicitly. ESP32 source rights, assumptions and geometry exceptions
persist with the project. Parameter restoration preserves the same admitted
explicit via-ID and fragmentation controls already supported by the worker.

The browser reuses existing unsaved-project review and cancellable project-load
sessions. Executable study wrappers are lazy text exports, byte-identical to
the existing files. Their separate gateway, resources and runtime are required;
five suspended thermal wrappers remain disabled. No new execution endpoint,
solver equation, runtime installer or implicit trust action is introduced.
Vite permits development reads from the two fixed example-resource directories.

A newly identified latest analysis replaces its previous envelope atomically.
Recursive retention must not combine an old run's raw fields with a new run's
normalized arrays or provenance. Saved-result presentation accepts current
normalized EMerge arrays as well as raw envelopes without modifying the source.

## Acceptance

Verify canonical write/read, deterministic hashes, exact source/result/script
identity, unchanged provenance, sample-pointer equality, malformed/tampered data,
source attribution, explicit geometry exceptions, all frontend snapshot setup
restoration, lazy asset transformation, suspended-state behavior, search and
project-replacement guards. Regress A-result -> B-rerun -> save/reopen so B
cannot inherit A's raw arrays. Installed visual acceptance and new physical
solves remain separate checks. See the [user guide](../EMERGE_EXAMPLES.md).
